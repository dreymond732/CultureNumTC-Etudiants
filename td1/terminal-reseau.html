Les commandes réseau vues comme dans un terminal

Observer les résultats de ping, DNS, traceroute et HTTP — sans lancer de véritables tests.

Simulation pédagogique — aucun réseau n’est testé. Les sorties affichées sont inventées pour apprendre à les lire. Elles ne décrivent pas le réseau de l’IUT de Toulon, de votre ordinateur, ni de votre Codespace. Les durées et certains résultats changent lors d’une nouvelle exécution. Ne confondez pas une simulation avec la commande exécutée sur votre poste local.

Comment utiliser cette page ?

Appuyez sur « Jouer la commande », observez chaque ligne jusqu’au résumé, puis cliquez sur « Commande suivante ». Les six exemples suivent l’ordre du TD. Les commandes ping, nslookup et traceroute sont à essayer sur un vrai ordinateur local (ou celui du voisin si vous utilisez une tablette). Cette page aide à interpréter leurs résultats ; elle ne les remplace pas.

1. Tester son propre ordinateur

Une adresse spéciale permet à un ordinateur de se répondre à lui-même.

Exemple prêt. Cliquez sur « Jouer la commande ».

etudiant@but-tc-toulon:~ — terminal simulé▣
etudiant@but-tc-toulon:~$ # choisissez « Jouer la commande »

Comment lire ce résultat ?

La question est : que permet de vérifier une réponse provenant de son propre ordinateur ?

Attention : une réponse locale ne démontre pas que la connexion Internet fonctionne.

Les repères à chercher dans les résultats

icmp_seq numérote les sondes de ping ; time= donne un délai en millisecondes ; packets transmitted indique combien de sondes ont été envoyées ; received combien ont répondu. packet loss est le pourcentage de sondes sans réponse. Par exemple, 4 packets transmitted, 0 received, 100% packet loss veut dire : « quatre sondes envoyées, aucune réponse, 100 % de perte sur ce test ». * * * dans traceroute signifie qu’une étape ne répond pas aux sondes : ce n’est pas nécessairement une panne. Les codes HTTP 200 et 404 seront manipulés au TD2.

Pour éviter de désigner de vrais équipements, les adresses utilisées dans les exemples de réseau sont des adresses de démonstration. Les sorties des commandes réelles peuvent différer entre Windows, macOS et Linux. L’affichage proposé reprend un style de terminal Unix, à titre d’apprentissage.
